# Ghidra edge-case ledger

This is the triage surface for behaviors that can invalidate a modern UI port. IDs are stable and
should be referenced by ADRs, issues, Protobuf comments, fixtures, and release-gate names.

Priorities are architectural: **P0** can corrupt data, cross authority, deadlock a workflow, or
make durable identities unsound; **P1** can produce materially wrong results, unrecoverable UX, or
unbounded resource use; **P2** is fidelity or compatibility debt that may initially have a visible
fallback. Solution labels are defined in the [research index](README.md).

## Cross-cutting conclusions

The repeated pattern is more important than any one row:

1. **Identity is contextual and epoch-bound.** Paths, addresses, database keys, version numbers,
   snaps, dynamic symbols, and UI rows are not globally durable.
2. **Cancellation is an outcome taxonomy.** It may roll back, leave valid partial state, kill a
   worker, commit a script's partial work, or leave a remote/live effect indeterminate.
3. **The project tree is a graph over layered storage.** Native IDE filesystem abstractions are
   useful presentation adapters but cannot define product semantics.
4. **Ghidra transactions protect domain-object changes, not an entire user workflow.** Approval,
   repository I/O, external artifact resolution, and target control live outside that boundary.
5. **Derived data needs provenance and completeness.** Decompilation, graph, diff, analysis,
   emulation, artifact acquisition, and agent evidence are revisioned result resources.
6. **Compatibility must be visible.** When a workflow remains Swing-only or extension-defined, the
   product reports and launches that boundary rather than silently omitting it or hiding it in a
   headless worker.
